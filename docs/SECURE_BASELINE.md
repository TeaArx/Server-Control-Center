# Secure baseline и оставшаяся дорожная карта

## Реализовано

- .NET 10 LTS, EF Core 10 и фиксированный SDK через `global.json`.
- Воспроизводимое восстановление NuGet через `packages.lock.json`.
- TOFU-проверка SSH host key. Доверенные fingerprints хранятся в
  `%LOCALAPPDATA%\ServerControlCenter\known_hosts.json`; изменившийся ключ блокируется.
- Структурная оценка риска команд вместо поиска опасных подстрок.
- Защита системных корней от изменения и удаления.
- Предпросмотр рекурсивного удаления с количеством файлов, папок и общим размером.
- Загрузка и скачивание через временный файл; удалённая запись создаёт резервную копию,
  восстанавливает исходный файл при ошибке и хранит пять последних копий.
- Ограничение встроенного текстового редактора: 2 MiB.
- Редактирование паролей, токенов, ключей API, Authorization и URI credentials в activity log.
- Явное различение отсутствующего и повреждённого DPAPI-секрета.
- Фабрика `AppDbContext`, singleton-ограничения для настроек/профиля, индексы и migration test.
- Резервная копия базы перед миграцией, пять последних копий и откат при ошибке запуска.
- CI для pull request и push в `dev`/`main`, unit/migration tests и release gate.
- Релиз только с коммита в `main`, SHA-256 checksum и поддержка Authenticode-подписи.
- Фиксированный version-tag Docker-образа интеграционных тестов.

## Настройка релиза

Для Authenticode-подписи в GitHub Actions задаются secrets:

- `WINDOWS_SIGNING_CERTIFICATE_BASE64` — PFX в Base64;
- `WINDOWS_SIGNING_CERTIFICATE_PASSWORD` — пароль PFX.

Пока сертификат не настроен, release workflow продолжает работу, публикует неподписанные
файлы и выводит предупреждение `Unsigned release`. SHA-256 checksum создаётся в любом случае.
После появления сертификата подпись включается автоматически без изменения workflow.

## Смена SSH host key

Сначала сверить новый fingerprint по независимому каналу. Затем закрыть приложение,
удалить только соответствующую запись из `known_hosts.json` и подключиться снова.
Удаление всего файла сбрасывает доверие ко всем серверам и не рекомендуется.

## Требует отдельного этапа или решения владельца

- Правила защиты веток на GitHub включаются в настройках репозитория; workflow не может
  безопасно назначить административную политику сам себе.
- Выбор лицензии является юридическим решением владельца; файл `LICENSE` не добавлен автоматически.
- Полная независимость дочерних feature ViewModel остаётся возможным следующим шагом.
  Сейчас XAML, code-behind, ресурсы и логика уже разделены по функциональным модулям
  с сохранением единого WPF binding-контракта.
- Общий SSH session manager, полноценная эмуляция терминала, PTY resize/reconnect,
  RESX-локализация, автоматическое обновление и accessibility regression suite требуют
  отдельных продуктовых и UX-решений.
